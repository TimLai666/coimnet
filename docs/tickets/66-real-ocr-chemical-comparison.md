# 66 — 使用者可以比較真實單字元辨識的化學回饋效益

Epic：TSK-11／MOD-02
User Story：判斷化學機制是否改善同一真實任務的學習。
Blocked by：64、65，兩票已完成工程驗收。
Status：done

## 交付範圍

沿用 ticket 64 的 KMNIST、人工 CPU 連續核心、單字元輸入、三個種子、資料分割與完整訓練預算，事前固定化學 ON／OFF 配對。化學組加入 ticket 65 的活動摘要來源、濃度、受體與暫時敏感度。控制器及反應係數固定，兩組可訓練參數數量相同。

使用通用 Trainer，OCR SDK 提供原模型及圖片輸入，完整快照用 TrainingBundle 保存。設定及比較規則見 [protocol.json](../../evidence/TSK-11/chemical-quality-20261013/protocol.json)。評估沿用已觀察的測試分割，沒有盲測宣稱，也不依結果選參數。

## 流程與驗證

官方原件 → 嚴格匯入及指紋 → 相同圖片及初始參數 → 獨立 ON／OFF 訓練 → 相同順序與更新數 → 凍結評估 → 配對差及成本 → 新程序讀回 → 證據及清理。答案僅用於分類損失及計分，化學來源沒有答案、回饋或資源輸入。

| 情況 | 本票驗收責任 |
| --- | --- |
| OFF 與原 OCR SDK | 預測及連續更新逐位相同，正式 OFF 快照重現舊結果 |
| neutral 化學設定 | 輸出、完整梯度及更新與 OFF 逐位相同，宣告可不同 |
| ON | 輸出及完整梯度有差異且有限，可訓練參數與更新預算相同 |
| 非法 group、空資料、匯入或數值錯誤 | 回錯並保留失敗，不算成功，不提交半次更新 |
| 取消或復原失敗 | 保持原件與其他模型 |
| 重複輸出路徑 | 不覆寫舊 bundle |
| 配對量測 | 序列執行並記錄資源，避免不等資源的速度宣稱 |
| 新程序載入 | 設定、最佳化器、輸出與下一次更新一致 |

## 驗收清單

## 減法審查

沿用既有 SDK、匯入及通用訓練器，不增加新 OCR 設定或分類核心。未證明有益時保持可選機制，不改預設。保留原始模型、資料及負面結果。

## Root 決策（2026-10-13）

固定每組 6,000 張訓練圖片、20 個 epoch 及 120,000 次更新。主要測試沿用 ticket 64 的 2,000 張，另在取得本輪品質分數前固定不重疊的 2,000 張確認分割。控制器及受體反應係數採明示工程設定，不增加可訓練參數。三個種子僅回答這組設定在本任務的配對結果，不推論所有化學設定或生物定量正確性。
