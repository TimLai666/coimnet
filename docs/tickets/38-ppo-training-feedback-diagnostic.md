## Root 決策 2026-10-04

固定 ticket 37 的六步設定、seed 1／2／3、各 200 更新及全部 PPO 參數。只新增測試範例診斷，保留訓練器、模型、公開 API 與前輪證據。

保存每次更新的環境種子、原提示、完整收集紀錄、回報、GAE 優勢與目標值、更新摘要與完整個體指紋。每 20 更新（含 0）在個體副本上做原／清除／反轉提示的左右 greedy 探測，使用 ticket 37 第一對環境種子 1001／1000。診斷探測不消耗訓練亂數。共 600 個訓練回合、198 個探測回合。目標只供診斷，不進模型。

最終指紋、每次回報／損失及終止統計須與同設定 RunPPO 相同，並與 ticket 37 已保存的結果核對。兩次新程序的報告須逐位元組相同。獨立核對以整數位置重播及獎懲公式重算，GAE 由逐步紀錄逆推。

假說與區分檢查：目標出現不平衡以全部與每 20 更新的左右回合數核對；成功回饋集中單側以各側抵達、最後成功更新與固定探測偏向出現時間核對；提示無法影響輸出以零狀態初步與後續原／清除／反轉輸出差異核對。差異只證明可達性，不證明有學會。

觀察性相關不宣稱唯一根因。若證據無法區分核心／價值競爭等機制，保留未知，再固定另一個介入方法。

## 流程、錯誤與責任

環境變數入口 → 固定設定 → 個體副本 collector → 重播合法性與 GAE → 原 rl.Update → 固定副本探測 → 排他建立完整 JSON。空紀錄、錯觀察／獎懲／終止、非有限值、非法動作或回報不符均拒絕。輸出存在時於訓練前拒絕，寫入失敗不得標成證據完成。新 helper 用手算成功／逾時案例及竄改回歸測試，先紅燈再實作。主 agent 負責實作與驗證，Luna 唯讀審查更新路徑，不能改任何檔案。
