# Ticket 57：使用者可以減少分段訓練重複計算神經元輸出的成本

**Epic:** 跨時間訓練與效能
**User Story:** 使用者可以保留相同模型、資料及訓練結果，讓分段重算共用同一神經元的輸出
**Blocked by:** 無；25 與 56 已完成
**Status:** done

## Root 決策（2026-10-11）

連續核心的段落前向與反向 drive，以及權重梯度，每條邊都重新活化同一電位。改為段落內保存活化輸出，保持邊宣告順序、乘加式、導數、延遲及截斷語意。

既有 `recomputeSegmentForward(ctx, p, inputs, cp, start, end, lambda, alpha)` 是內部格子。回傳該段電位與輸出兩組列及錯誤。前史電位唯讀共用，前史輸出與新列由本次呼叫持有。`driveRow` 改讀已活化的輸出，不再於邊迴圈活化。相鄰相同延遲的邊共用一次選出的列，邊的乘加順序保持。已由公開入口及建構器驗證的來源、目標、延遲及權重列在迴圈前切成相同長度，讓編譯器移除重複的邊索引檢查。連續相同目標的邊以 float64 暫存同一目標的驅動累加值，換目標時先存回，再讀新目標既有值，結尾存回最後一個目標。任何邊都不重排，乘加式不改寫。反向權重梯度讀同一組輸出。`ForwardRecompute` 交付段落的新輸出列，消除再次活化。檢查點只保存電位，新增輸出暫存限於單段及必要前史。零連線的反向不使用輸出，以內部 needOutput 旗標略過活化暫存；零連線公開前向保留原本逐列計算輸出的方式，避免新增活化前史。無需新公開 API、設定、依賴或快照欄位。

## 量測契約

使用固定人工圖，2,048 節點，64 步，段長 16，tanh 與 softplus，各 64 條／節點的扇出，延遲 0／3。固定參數與非零輸入，測公開 ForwardRecompute、BackwardRecompute。另保留每節點一邊及零邊的控制，不用小圖推論全圖加速。

測試 worker 寫公開行為回歸及 Go benchmarks。Root 審查、執行與凍結後才派另一位 worker 填實作。效能變更的先失敗證據為修改前 benchmark 本身無法達到改善門檻，正確性控制在基準版本須通過。不得用不穩定牆鐘門檻作單元測試。

修改前及修改後測試執行檔保存在本輪 `runs/.tmp/`。至少七次交錯配對、每次獨立程序、GOMAXPROCS=1 與相同 benchtime。高扇出兩種活化的前向與反向時間中位數至少改善 15%，記錄所有單次資料與記憶體配置。另以獨立程序 RSS 核對新增段落輸出暫存，記錄共用 Mac 負載。若門檻未過，繼續找根因，不調模型或弱化判準。
