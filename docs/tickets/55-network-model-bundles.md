# Ticket 55：使用者可以把模型存在網路磁碟並讀回接續

**Epic:** 模型保存與恢復
**User Story:** 使用者能在網路分享資料夾保存模型、個體與訓練狀態
**Blocked by:** SMB 保存與接續可直接驗證；完整套件的單檔發布需要原生磁碟驗收
**Status:** in_progress

## Root 決策｜2026-10-10：沿用資料夾模型格式

使用者要求框架支援模型存到網路磁碟。沿用既有 v2 資料夾格式與三種 Bundle API，資料寫好後才寫完成清單。完成清單缺失或不完整時，載入必須拒絕。同時保存只有一個執行者成功，既有檔案與目錄保持。完成清單完整寫出後，取消或同步失敗須保留可讀成果並明示狀態。舊單檔模型、版本、數值與讀取保護保持。

| 觸發／操作 | 預期結果 | 驗收 |
| --- | --- | --- |
| SMB 上保存三種狀態 | 無需 hardlink，可讀回與接續 | 既有 Bundle SDK 與新程序 |
| 既有檔案、空目錄或同時保存 | 拒絕既有目標，只有一個成功 | 原件指紋與並行回歸 |
| 完成前取消或寫入錯誤 | 不留下可接受的半成品 | 清理與截斷清單回歸 |
| 完成後取消或同步失敗 | 保留成果，回報已發布與耐久性狀態 | 狀態回歸與讀回 |
| 網路中斷或伺服器故障 | 回報錯誤，不能宣稱遠端耐久性 | 可實測範圍與限制明示 |
| 舊資料夾模型與單檔模型 | 既有格式與讀取行為保持 | 原件與完整檢查 |

## 減法審查

沿用既有資料夾格式、驗證與 SDK，不新增 SMB 連線套件、憑證設定或模型格式。不把普通重新命名當作不覆寫保護。

## 實際驗證與限制

最後來源的資料夾專項一般 23 個頂層測試通過；race 22 個通過，既有的大容量案例因 race 記憶體成本略過，一般測試已通過。三種 SDK 模型在新程序讀回後接續，完整狀態與不中斷的參考相同。兩個獨立程序同時保存只有一個成功，勝方三種模型可載入與接續。

保存格式與九個模型檔案逐位元組相容。舊 v2 對照是修正前在發布失敗前擷取的完整檔案副本，並非當時成功發布的模型。建置、vet、模組完整性、依賴檢查與 11 個治理專項通過。完整一般與 race 在最後兩個檔案的錯誤處理補強前啟動，不能宣稱最後來源的完整套件通過。舊單檔、圖、參數及下載發布在本分享磁碟不支援；原生磁碟完整驗收保留為未完成。

證據見 [最後專項](../../evidence/STA-01/network-model-20261010/bundle-final-green.log)、[新程序讀回](../../evidence/STA-01/network-model-20261010/sdk-final-readback.json)與 [Root 審查](../../evidence/STA-01/network-model-20261010/root-review.md)。沒有實測 NAS 斷線或檔案同步／關閉失敗，不能保證伺服器故障後的資料耐久性。
