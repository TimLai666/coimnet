# Ticket 56：使用者可以對合法大型模型開啟分段重算訓練

**Epic:** 跨時間訓練與記憶體
**User Story:** 使用者可以用同一模型及資料切換完整歷史與分段重算，得到相同的訓練結果
**Blocked by:** 無；25 的重算能力已驗證
**Status:** in_progress

## 問題與共用契約

訓練的重算前向經持續狀態 API，將個體輸出及歷史的容量限制帶入有限序列。完整歷史可訓練的模型因而可能只在重算時失敗。沿用兩種核心既有段落運算，前向只保留目前段落及實際已有的延遲前史，完整輸出仍保存。

新增兩種核心的 `ForwardRecompute(ctx, parameters, initial, inputs, segment)`，回傳輸出矩陣與錯誤。連續輸出是活化值，LIF 輸出是突觸跡。既有方法、模型設定、保存格式、最佳化器及持續個體容量保護保持。

## Root 決策 2026-10-11：骨架與驗收

| 操作／條件 | 結果與錯誤處理 | 證明方式 |
| --- | --- | --- |
| 合法序列跨段、有延遲、自我／重複邊、非零初始值 | 與完整歷史輸出相同 | 兩種核心逐位比對，LIF 含適應、不應期及慢速穩定 |
| 短序列但宣告極長延遲 | 使用時間零的前史，不依宣告延遲配置巨大陣列 | 兩種核心及 Trainer 公開入口，延遲為 MaxInt |
| 實際延遲歷史超過持續個體上限 | 重算訓練成功且與完整歷史相同 | 公開 Step／StepFrom、參數與最佳化器比對，持續狀態仍拒絕 |
| nil、取消、空序列、錯誤形狀、NaN／Inf、無效段長 | 回錯、不回傳部分輸出、不修改輸入及模型 | 新前向 SDK 錯誤與所有權回歸、既有錯誤控制 |
| 大段長及段長大於序列 | 一段處理完成 | 1、4、7、超過序列及 MaxInt 段長 |

流程：觀察 → 編碼 → 分段核心前向 → 讀出 → 損失 → 原分段反向 → 候選參數更新。所有失敗由既有錯誤回傳交給呼叫者，不發布半次更新。沒有資料庫、相依性或檔案遷移。

## 分工與減法審查

Root 固定上述簽名、結果與驗收。測試 worker 只新增兩份回歸，Root 審查並凍結。實作 worker 只能填入兩種前向及既有 observe，不得修改測試。

直接移除重算路徑對持續個體 API 的依賴，不提高所有持續狀態的上限，不新增設定或外部工具。此票不調整模型、導航任務、GPU 或既有反向公式。
