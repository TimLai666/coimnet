## Root 決策（2026-09-15）

### 共通（所有階段）

1. **任務套件結構**：`tasks/<name>/`（`ocr`、`asr`、`textgen`、`media`）各自提供：`Dataset` 讀取器（資料
   規格 + 授權欄位 `License{Holder, Terms, Source}` 必填）、`Preprocess`、`Adapter`（編碼與映射，走
   `signal`）、`Loss`（走 26 的 `LossGradientFrom`）、`Train`／`Infer`／`Evaluate`、保存恢復（沿用
   checkpoint）、`examples run <task>`（離線範例，不需金鑰、不下載）、`import`（真實資料匯入範例，只在
   使用者提供路徑時執行）、對照流程（28 的歸因矩陣的子集）。人工資料只證明程式能運作，報告欄位
   `data_scope` 明寫資料範圍、語言、解析度、序列長度與外圍模型；原生核心模式的輸出不能繞過核心（測試：
   斷開核心後輸出必然改變）。
2. **TSK-11 的處理**：每個任務的真實資料 adapter 都寫成可測（以 fixture 檔跑通），但「真實授權資料上的
   匯入、訓練、推論與評估」四項證據需要使用者提供資料；在此之前 `docs/requirements-status.json` 的
   TSK-11 維持 `specified`，ticket 標 blocked 並列出需要的資料格式清單。

### 第一階段：OCR（TSK-01）

3. 資料：PNG／JPEG 單行影像 + Unicode 文字；頁面契約 `Page{Image; Blocks []Block{Bounds; ReadingOrder;
   Text}}` 與把區塊送進同一辨識器的流程；基礎切分是規則式（投影法），文件明寫限制、不宣稱任意版面。
   保存影像尺寸、色彩空間、縮放方法、文字方向、區域座標。編碼：固定的像素區塊編碼器與可訓練小卷積（Insyra
   的 `nn`）兩種對照。輸出是字串（CTC 解碼）加可選區域，不是單字分類。
4. **CTC**：`tasks/ocr/ctc`：log-space 前向；極小字母表（2 個字元 + blank）上枚舉所有路徑對照（主規格
   18.2）；連續重複字、空目標、長度不足、blank 位置測試；無合法路徑回 `ErrNoValidPath`（不把無限損失
   設成零；若提供 `ZeroOnImpossible` 策略必須顯式設定並計數）。CER = (替換 + 刪除 + 插入)/參考字元數，
   空參考另定義（回報 `undefined` 而不是除以零）。Fixture：程式生成的點陣字形（不夾帶字型檔），繁體
   中文、大小寫、不同背景、未見組合、空影像、破損檔；字形集合訓練／測試分開（字型與版面母本不跨洩漏）。
5. 證據 `evidence/TSK-01/`（fixture）；真實資料段 blocked。

### 第二階段：語音轉文字（TSK-02）

6. 資料：WAV PCM + 文字稿 + 取樣率、聲道、說話者、錄音場次；壓縮格式只經顯式解碼器整合（本票不做，
   `doctor` 顯示缺少）。分割以說話者／場次為單位（測試：同一場次不出現在兩邊）。前處理：重取樣（宣告
   方法）、混音、音量正規化、STFT 與 log-mel（固定視窗、步長、濾波器版本寫進報告）。
7. **兩種模式**：整檔；串流（分塊，狀態接續，只用已到達的音訊，不用整檔統計：測試把未來區塊填 NaN 標記，
   輸出不變）；斷線後從快照恢復、尾端不足一窗、最終 flush 三個測試。輸出文字（CTC 解碼），CER／WER
   可重現（同 seed 逐位相同）。推論時間與串流延遲量測寫進報告（附 `uptime`）。沒有人工時間標記時不報
   對齊精度；聲音分類只作內部測試不算完成。
8. 證據 `evidence/TSK-02/`；真實資料段 blocked。

### 第三階段：文字生成（TSK-03）

9. Tokenizer：位元組基準（處理任意 Unicode）+ 可替換詞表介面，設定（含格式、角色、特殊 token）可保存與
   重現（`VocabHash`）。訓練：已知前綴預測下一個 token，遮掉填充與不計分前綴（測試梯度為零）；資料切分
   以完整文件／來源為單位；教師文字保留來源並去除與測試重複（27）。生成：起始狀態、最大長度、結束
   token、溫度／top-k／top-p 採樣（seed 可重現）；串流位元組解碼處理不完整 UTF-8（緩衝，不靜默刪字元，
   測試以切在多位元組中間的邊界）。評估：NLL、perplexity（不同 tokenizer 不排名，報告帶 `VocabHash`）、
   任務正確性、生成有效率；保留語料；教師移除評估（27 的 `student` 模式）。文件明寫「沒有實驗前不宣稱
   中文對話、推理或知識能力」。
10. 證據 `evidence/TSK-03/`；真實資料段 blocked。

### 第四階段：文字條件影像與音訊（TSK-04、TSK-05）

11. 核心生成流程：文字經編碼與核心，核心產生可還原表示（低解析度像素區塊 8×8×3 或音訊區塊 256 樣本），
    受控解碼器還原；訓練時目標影音只進損失；**推論時解碼器不讀提示文字**（型別：解碼器的輸入沒有文字
    欄位；汙染測試）。報告編碼器、核心、解碼器的參數量與訓練分工（`CapacitySplit`）。影像輸出 PNG，
    音訊輸出 WAV（取樣率與長度精確，測試誤差為 0 樣本）。評估：保留條件的內容符合度（fixture 的形狀／
    聲音事件是否受文字控制，以獨立的分類器量測）、時間一致性、外圍容量對照；文件明寫「像素 MSE 好看
    不代表感知品質」「只證明有限任務的生成」。
12. 證據 `evidence/TSK-04/`、`evidence/TSK-05/`；真實資料段 blocked。

### 第五階段：影片與同步音訊（TSK-06）

13. 從文字條件生成影格序列 + 對齊音訊，輸出 PNG 序列、WAV 與時間線清單（JSON：每格時間、音訊區塊
    起訖）；可選封裝器（ffmpeg）以參數陣列呼叫（`exec.Command` 的 args，不拼 shell），沒有封裝器時原生
    輸出仍完整（測試：封裝器缺席時路徑非空、檔案存在），`doctor` 顯示封裝器依賴與版本。評估分開展示：
    影像、時間變化、聲音、跨兩者同步（fixture：軌跡與聲音事件的時間對齊誤差）是否受文字條件控制；
    依賴失敗可驗證（封裝器回錯時報告記錄錯誤而不是假成功）。
14. 證據 `evidence/TSK-06/`；真實資料段 blocked。

### 第六階段：固定還原器與外部工具模式（TSK-07）

15. 固定還原器：使用已訓練且鎖定的還原模型（fixture：一個凍結的小自編碼器），核心學產生它接受的表示；
    驗證表示分布、時間對齊與獨立解碼品質，報告明示還原器提供的能力。外部工具流程：核心輸出工具請求
    （27 的 `tool.Registry`），外部模型產生影音；結果標 `role: external_tool`，**不計入核心生成能力**
    （報告欄位分開，測試：核心能力指標不含工具結果）；外部呼叫依授權、預算與資料政策（27）。三條流程的
    模型與角色可查（`RoleReport{CoreGenerated, FixedDecoder, ExternalTool}`）。
16. 證據 `evidence/TSK-07/`；文件：README 任務表與科學界線。

## 第二階段資料與範例增量（2026-09-23，局部驗證）

`ReadDataset` 以帶授權欄位的 manifest 匯入 PCM16 WAV，核對宣告的取樣率和聲道，記錄原檔 SHA-256、混音／線性重取樣／峰值正規化結果；拒絕路徑逃逸、重複鍵、不可為 `null` 的欄位及超過 16 MiB 的 manifest。來源 SHA 與解碼使用同一次讀取的位元組；預設每檔原始 64 MiB、每檔處理緩衝估算 512 MiB、全批估算 2 GiB，上限可明示調整且不是 RSS 承諾。`SplitBySpeakerSession` 把共享說話者或場次的連通群放在同一分割，單一連通群時回錯；不均群組在有界工作量內找全域最接近目標的分割，超過界限回錯。人工 WAV 端到端測試確實走過匯入、分割、訓練、整檔及串流評估。

`MeasureStreaming`／`EvaluateStreaming` 回報每筆串流的文字、CER／WER、音訊長度、逐塊本機耗時與第一次有文字輸出時收到的樣本數。`examples run asr` 只在記憶體產生人工音調，不下載或保存模型。保留集 10 筆、19 字元，整檔 CER 從 13/19 降至 12/19，WER 前後都是 9/10；串流評估 CER 為 12/19。這只證明小型 fixture 的框架流程，沒有自然語音能力結論。

[TSK-02 驗證紀錄](../../evidence/TSK-02/verification.json) 保存兩次 CLI 報告、原始量測、來源指紋，以及完整測試／race／vet／build／相依性檢查結果。Mac CPU 路徑通過；Ubuntu 1 本次 SSH 認證失敗，沒有跨平台結論。`TSK-02` 仍為 `specified`：`StreamState` 缺專用嚴格檔案載入器、容量限制與原子落盤；真實授權語音上的匯入、訓練、推論、評估歸 TSK-11，仍為 blocked_data。
