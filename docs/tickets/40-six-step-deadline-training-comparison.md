## 已確認方法

使用者已確認接續六步任務期限的訓練對照。保留原模型、公開 API、預設訓練與所有舊證據。只在測試範例新增兩組：原收集截斷（計入逾時後續價值）、六步任務期限（逾時後續價值為零）。到達目標與期限耗盡仍分開計數。

兩組沿用 ticket 37 的固定設定：seed 1／2／3、各 200 更新、走廊 7 格、兩個時限均 6、8 hidden、學習率 0.01、每步扣 0.01、目標獎勵 1。PPO 的 gamma 0.99、lambda 0.95、clip 0.2、value 0.5、entropy 0.01、burn-in 0、epoch 1、mini-batch 1 都不變。初始模型、訓練 RNG、環境種子、更新器及評估預算相同。訓練策略分歧後的取樣動作不宣稱逐回合配對。

期限組將合法收集紀錄的最後一個 Timeout 轉成 Done，BootstrapValue 設零。成功的 Done 不變。保留轉換前的最後一步，讓環境抵達／逾時、原後續價值與訓練終止各自可核對。collector 已在副本上多處理的下一筆觀察只取得診斷價值，不消耗行動 RNG，不改訓練個體。此組不新增第七個環境動作。

兩組都保存 600 更新的輸入、行動、機率、價值、獎懲、原終止紀錄、訓練 rollout、GAE、PPOReport 及前後快照指紋。原組全部更新須等於 ticket 38，完整評估須等於 ticket 37。新組的結果無論通過或失敗都保存，不再搜尋參數。

## 流程與錯誤責任

環境變數入口 → 排他輸出前置檢查 → 固定來源指紋 → 兩組初始化與收集 → 範例內的期限轉換 → 原 rl.Update → 副本評估 → 保存完整報告。入口負責既有輸出、來源、寫入及關閉失敗。轉換負責空回合、不合法時限、過長／提早逾時、終止衝突、提早終止、非有限值與獨立拷貝。訓練負責 nil／取消 context、不合法設定、收集及更新失敗，失敗不回傳半套成果。原獎勵與成功計分不因 Done 改名而改變。

## 骨架與分工

- 主 agent 固定型別、簽名、上述期望與證據入口。
- 測試 agent 只修改 `experiment/ppo_horizon_validation_test.go`，對手算、正常、失敗及拷貝寫測試。主 agent 審查並在空骨架執行，確認紅燈。
- 不同實作 agent 只填 `experiment/ppo_horizon_helpers_test.go` 的兩個函式，不得改測試。
- 主 agent 審完整 diff、重跑、完成報告及獨立核對。外部分工依使用者指定的新 agent-delegation 規則使用 OpenCode 免費模型。審查不能取代主 agent 驗證。

## 完整驗收流程

1. 手算三步成功／逾時回合經期限轉換後，GAE 等於真正終止的手算值，原回合及觀察保持不變；不合法輸入全部拒絕。
2. 同初始模型的短訓練，原組等於既有訓練器；期限組只改末步終止及目標，逾時不能被當成抵達。取消與錯設定不回傳半套紀錄。
3. 兩個新程序產生相同兩組報告，每組 39 條件、1,560 評估回合。以 ticket 37 的左右配對、提示清除／反轉及完整原判準判讀，所有 seed 都通過才記能力門檻通過。Python 獨立重算環境、GAE、摘要、原組一致性與判準，保留全部失敗結果。
