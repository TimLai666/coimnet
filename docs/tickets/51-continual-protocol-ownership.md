# Ticket 51：研究者可以保留連續任務執行當時的設定

**Epic:** 訓練框架的可保存設定
**User Story:** 研究者可以修改後續任務設定，而先前報告的宣告、識別與結果保持一致
**Blocked by:** 無；50 是來源基準
**Status:** completed

## Root 決策｜2026-10-09：問題與共用契約

連續任務入口直接保存呼叫端的 Protocol。任務參數、階段、種子、比較設定與化學狀態列都共用可變資料。回傳後修改設定會改到舊報告，執行期間的 builder 回呼也能改到正在執行的設定。入口在原有驗證通過後、計算雜湊與呼叫 builder 前，複製完整可變設定。呼叫端與每次執行各自持有資料。

| 條件／操作 | 預期結果／處理 | 本票驗收 |
|---|---|---|
| 呼叫端回傳後修改任務與參數、階段、種子、比較與化學狀態 | 完整舊報告及 protocol_hash 保持 | 雙向修改回歸 |
| 修改第一份報告與追加預留容量 | 呼叫端及第二份報告保持 | 報告間隔離回歸 |
| builder 在同一個 goroutine 修改呼叫端資料 | 本次設定與結果等同未修改的控制組 | 執行前複製回歸 |
| nil 可選指標、nil 與非 nil 空化學列 | 原本合法的 JSON 表示與錯誤次序保持 | 空值控制 |
| 取消或 builder 失敗 | 既有錯誤與部分報告保持，回傳資料仍隔離 | 錯誤控制 |
| 合法訓練、比較與 CLI | 完整報告與修改前逐位元組相同 | 原提交與兩個新程序對照 |
