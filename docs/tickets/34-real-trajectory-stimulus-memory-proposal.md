# 34 — 使用者可以比較含刺激歷史的軌跡模型與無記憶控制組

Epic：TSK-11 真實任務資料

User Story：使用者可以知道模型是否利用搬移前已發生的刺激與移動歷史，而不是只延續上一個方向。

Blocked by：觀察與學習方法的決策。推論隔離由 ticket 33 驗收。

Status：proposed（2026-10-03）。尚未實作，也未核准新模型方法。

## Root 方法草案（2026-10-03，待核准）

保留現有 `realnav` v1 範例，另做以觀察位置與已發生刺激為輸入的工程代理模型。第一個切片是完整試次的刺激記憶與模仿學習，使用真實記錄的下一步位移作標籤，再以自主行走及控制組評估。這個方案能檢查刺激歷史是否改善回到評分區的結果。資料沒有可靠感覺或控制命令，因此驗收只適用於這個明示輸入的工程模型。

需要使用者決定的是：接受上述工程代理，或要求先找到具備感覺／動作記錄的來源再訓練導航。前者能沿用已授權資料，但不能用結果宣稱重現果蠅神經機制；後者需要重新稽核資料格式、權利與可用性。

## 核准後的最小切片與驗收

1. 來源 → 分割：固定原 13 個 test 試次，只從原 26 個 train 試次事前切出 validation。保存實際清單、分層規則與指紋，再選訓練設定。三組互斥、完整覆蓋；禁止拿 test 選參數或排除失敗。
2. 過去紀錄 → 模型：目前位置、上一位移與時間差沿用觀察代理。刺激只按過去列推導：rewarded 且 LED 正值標為 delivered stimulus，non-rewarded 正值另標為 scheduled-only metadata，兩者不能混成 reward。模型只接收 delivered stimulus 歷史。把儀器記錄時間當成工程觀察時間是明示假設，神經獎勵到達時間保持未知。ID、condition、segment、搬移量及目標位置不成為輸入特徵。
3. 歷史 → 學習：同試次從零狀態開始，保留刺激前後的神經狀態，搬移期間的狀態處理須先固定為工程假設。用搬移後的下一位移作模仿標籤，梯度不得在歷史與標籤之間中斷。不能沿用 256 步重設後宣稱有跨區段記憶，也不能把觀測位移當成動物控制命令。
4. 凍結模型 → 評估：目標位置由 evaluator 單獨持有。自主行走沿用固定工程場地與門檻，同時報告模型、無刺激歷史、刺激歷史打亂、方向延續及隨機控制。可訓練模型控制組的初始化、參數容量、訓練預算與試次相符；訓練前後及所有失敗都保存，不預先承諾命中率。
5. 驗收與交付：先寫時間／未來資訊、刺激語意、試次污染與狀態連續性的失敗測試。確認未來目標或 metadata 改寫不影響既有模型輸入，再驗證資料匯入、訓練、新程序推論及自主評估。軟體通過和導航改善分開記錄，TSK-11 的整體驗收仍依 ticket 29。

失敗或部分資料：來源指紋錯誤、非有限值、非遞增時間、空／重複／未知試次與缺必要欄位都拒絕。刺激零值是已記錄的零，缺值保持未知並禁止產生虛構 reward。取消或輸出已存在時沿用現有排他寫入契約；先完成資料驗證再建立輸出。超出已宣告的 episode 或記憶體容量時回錯並報告，不能截斷歷史後繼續當成完整試次。

## 減法審查

沿用原資料授權、試次 ID、完整分割、CPU 核心、凍結推論及評分器。先移除「把 LED 正值直接當 reward」的假設，不新增未知回饋的假分數或新的強化學習演算法。新模型只放範例，原始資料與模型留在 Git 外。一般格式名稱及內部實作由 root 在方法核准後定案，不另要求使用者決定。
