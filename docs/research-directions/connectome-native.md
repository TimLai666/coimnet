# 研究方向：Connectome 原生模擬與可學習模式並列

使用者於 2026-09-14 定下的方向。它補在主規格之上，不取代 85 項原始需求；新增需求用
NAT 編號，定義在 [requirements-addendum.json](../requirements-addendum.json)，狀態與原始
需求一起記在 [requirements-status.json](../requirements-status.json)。

## 兩條一級路徑

1. **Connectome 原生模擬**：以真實接線為主要結構，為神經元與突觸加上明示的動態規則
   （累積、放電、興奮／抑制、傳播），不要求先用梯度或其他學習方法。直接輸入感覺刺激，
   觀察指定神經元的輸出。
2. **可學習模式**：在同一份接線與動態之上加入可調整機制（突觸權重、神經元參數、調節、
   獎勵訊號、局部可塑性），之後才考慮監督、強化、持續學習與蒸餾。

兩者共用同一份接線、同一套動態模型與同一組輸入／輸出轉換，差別只在是否開啟學習機制。
不得為了套用現成機器學習工具把接線改成一般人工神經網路；也不得讓原生模擬變成必須先過
訓練器或編碼器才能執行的附屬功能。

## 五層分離

| 層 | 目前對應 | 可替換方式 |
| --- | --- | --- |
| 生物原始結構 | `connectome` 視圖與 GraphStore（拓撲、原始 weight、註記、預測） | 不可變；換資料集或選取條件就是另一份衍生物 |
| 神經元／突觸動態模型 | `dynamics.Continuous`、`dynamics.LIF` | 同一張圖可換模型比較 |
| 動態參數來源 | 目前為人工初始值；ticket 13 由發布資料推導 | 參數集檔案可替換，每份帶推導規則與未知計數 |
| 感覺輸入轉換 | 目前為可訓練 encoder；ticket 12 加固定注入 | 固定注入與可訓練映射都是明示的模式 |
| 運動／行為輸出轉換 | 目前為可訓練 readout；ticket 12 加指定神經元探針 | 探針與判讀協定可替換 |
| 學習與可塑性 | AdamW 訓練器；可塑性與調節待做 | 關閉時必須還原原生行為 |

## 兩條不能省的原則

- **未訓練不等於沒有假設。** 接線裡沒有突觸強度、正負號、時間常數、閾值與延遲。原生模擬
  的每個參數都來自明示規則（例如「權重與突觸數成比例」「乙醯膽鹼為興奮」），報告必須寫成
  「接線加規則 A／B／C 產生了 X」，未知保持未知，不得補零或固定正負號（主規格 3.2、7.4）。
- **歸因必須有空模型。** 要說某個行為來自原始接線，至少要跟保留度數分布的隨機重連、
  打亂正負號與打亂權重的版本比較；只換動態模型分不出接線與參數的貢獻。

## 評估要回答的問題

| 問題 | 需要的能力 | 需求 |
| --- | --- | --- |
| 完全不訓練時，接線本身能產生哪些輸出？ | 原生 runner、固定注入、探針 | NAT-01 |
| 參數從哪來、哪些是假設？ | 參數 adapter 與推導報告 | NAT-02 |
| 哪些輸出來自接線而不是參數或巧合？ | 空模型對照 | NAT-03 |
| 「有行為意義」怎麼定義？ | 具名神經元集合與判讀協定 | NAT-04 |
| 換動態模型後哪些輸出仍在？ | 同圖多模型比較 | NAT-05 |
| 加入可塑性後原有輸出被增強、修改或破壞？ | 學習前後對照矩陣 | NAT-06 |
| 能否保留原始結構又學會新任務？ | 可學習模式對照 | 原 W08–W11 需求 |

## 現有架構的檢查結果（2026-09-14）

- `dynamics` 兩個核心都不依賴訓練器；`connectome` 的視圖與 GraphStore 不含任何訓練資訊。
- 唯一的「感覺→核心→輸出」管線在 `learning.Network`，預設接 Insyra 的可訓練 encoder／
  readout；凍結執行可行，但原生模擬需要不經這兩者的 runner。這是新增，不是重構。
- LIF 目前只有整段 `Forward`／`Backward`，沒有持續狀態的 `Advance`，原生模擬必須補。
- 正負號未使用（邊的 sign 一律 unknown），突觸數只在範例當初始值，細胞類型參數與延遲
  沒有資料來源。發布內可用的量見 [發布盤點](../malecns-release-catalog.md)。
- 全腦規模在 CPU 可行：165,122 個選入節點、25,563,197 條邊，LIF 每步約 2.6×10^7 次邊運算。

## Ticket 順序

1. [12 LIF 持續狀態與原生模擬 runner](../tickets/12-native-runner.md)：`dynamics.LIFState`
   與 `Advance`；`simulate` 套件以固定注入、探針與監控執行任一核心；CLI `simulate run`；
   真實全圖的容量與時間實測（參數為明示的工程假設）。
2. [13 發布資料到動態參數的 adapter](../tickets/13-parameter-adapter.md)：納入 `body-stats`、
   `tbar-neurotransmitters`、`syn-partners`、`Neuprint_Meta.csv`；逐邊正負號與信心度、權重
   正規化、ROI 與細胞類型標籤；參數集檔案與推導報告。
3. [14 空模型與行為判讀協定](../tickets/14-null-models-and-behavior.md)：度數保留重連、
   正負號與權重打亂；具名神經元集合、指標與門檻；同圖多模型、多對照的比較矩陣。

可學習模式沿用既有 `learning`，之後在 runner 之上開啟可塑性（NAT-06）。受體表現不在發布
內，另開外部資料 adapter 票時再定義 `ReceptorRecord` 的來源與細胞類型對應。
