# GPU 取消與恢復稽核

原始目標是排查框架中會影響模型品質的缺陷。本票補上上一輪未實測的 GPU 更新階段，不改正常模型數值或保存格式。

## 固定驗收

1. 核對公開 Step／StepChecked、GPU Trainer Step／StepFrom、裝置讀回與提交位置。每個實際檢查點記錄檔案、行號與遇到次數，不能用初始化前取消替代更新中取消。
2. 在硬體執行有效非零梯度控制，取消前已有非零動量及更新歷史。錯誤須保留完整參數、第一／第二動量、計數與 Trainer 累積窗。原物件重試與不中斷對照一致。覆蓋凍結遮罩、零排程學習率、部分累積與滿窗更新。
3. 一般及 race 版本、新程序 JSON 恢復與相同建置對照通過。保存完整來源指紋、執行命令、裝置身分與實際輸出。沒有硬體或位置未到達就明示缺口，不改測試放行。
4. 保存證據後只清除 runs/.tmp/gpu-cancel-audit-20261015，原資料、模型、模組來源及原有暫存保持。完成來源核對、已授權提交／推送及遠端讀回。

Root 擁有測試探針、正式程式與共享文件。分工只審查來源及探針是否涵蓋契約，不改測試、正式來源或 Git。只有確認失敗後才建立永久失敗回歸與最小修正。完整工程測試可沿用來源逐份相同的上一輪證據，另重跑相關一般／race、build、vet、相依性、格式與治理。

三區塊測試沿用既有 newChunkedHardwareAdam，僅在測試物件把邏輯容量減為 64 個值，130 個值在真實 Metal 上分三區塊執行。這不量測原生硬體容量。另用新增測試檔的 Go overlay 唯讀存取既有 deviceAdam.Snapshot，比較選中 GPU bank 的完整設定、參數、動量及計數。沒有改正式方法或公開契約，這 1,624 點是既有 Trainer 點的補充觀察，不重複加入總數。Snapshot 會增加讀回計量及改變時序，scratch、未選 bank 與診斷計量不要求不變。

跨建置浮點差異並列查證最早分歧的值，先取得可重現中間值及獨立取整參考。診斷可能改變編譯結果，須保留未插入診斷的控制，不能因加入記錄後差異消失就宣稱修正。

【減法審查】

- Won't List：不新增 GPU 模式，不以硬體小圖推論全腦效能或真實辨識率。
- 建議移除：直接使用標準取消與公開快照，無需正式測試鉤子。
- 建議簡化：同一份來源／探針搭配一般與 race 建置，與各自不中斷控制比較。
- 需要留意：建置差異與取消交易分開判斷，不能把極小數值差異當成已確認品質缺陷。
