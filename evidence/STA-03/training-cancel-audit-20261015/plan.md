# 訓練取消與狀態保存稽核

原始目標為確保框架沒有 bug，沒有已知總數。本票四項只是可驗證的稽核里程碑。

公開入口為 TrainEpisode、Step／StepFrom／StepFromState 與裝置 AdamW 候選提交。取消在最後有效提交之前被觀察時回錯並保留上一個有效狀態。取消晚於提交的成功不列為缺陷。

Root 使用真正 context.WithCancel 包裝器，在第 N 次 Err 查詢時呼叫標準 cancel，Done 與 Err 保持一致。逐一掃描一次合法訓練所觀察的全部檢查點，沒有 sleep 或私有欄位注入。每次以同一份合法公開快照恢復，保留持續歷史及已存在的累積窗，再比對完整快照、暫時化學報告、JSON 保存與恢復後重試。新程序接續另行驗證。

不中斷訓練作為正常對照，取消後重試須得到相同結果。來源審查與實際執行分開，未執行 GPU runtime 就只回報來源審查。不新增正式 helper、狀態格式或 API。

檢查取消前、等待鎖、計算中、部分／完整累積窗、重算與共享、化學 controller 歷史及候選驗證。探針形狀錯誤先修正並保存原失敗，不當作框架缺陷。若找到正式缺陷，Root 先寫可失敗永久回歸，再派最小修正，worker 不得改測試。正式來源保持時，沿用同一來源的上一輪完整工程證據並新增本票相關驗證。

【減法審查】

- 建議移除：不用隨機 sleep、重訓整個真實模型或新取消 API。
- 建議簡化：以標準取消包裝器逐個檢查點驗證同一公開快照。
- 需要留意：小圖狀態契約不作為全圖效能、真實辨識率或框架零 bug 的證據。
