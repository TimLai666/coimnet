# Root 驗收判斷

目前完成四項驗收，12 組訓練、完整狀態與同圖片品質已通過。最後治理已通過，主暫存清理完成，提交與遠端讀回待完成。以下保留完成分析前的審查紀錄，最終結果見 README.md 及 root-results.json。

## 審查結果

- Root 重算四種索引與訓練圖片分布，逐檔核對六份原件及副本，結果符合資料 worker 的報告。`preflight.json` 記錄開跑前的固定資料與協定，測試分割不參與調參。
- 一般與競態建置的初始完整模型、設定及資料選取相同。各五項 driver 測試及十張圖片的公開 OCR／通用 Trainer 等值控制通過。active 的「不同」只證明作用確實啟用，沒有被當成數值正確性的證明。
- 現有同參數族的獨立化學手算前向及全路徑有限差分，已在本輪完整一般測試中通過，見 `engineering-progress.json`。另有四列 mixed 的獨立完整參考。這些證據支援機制契約；本輪沒有建立 52 節點每一個數值的獨立 oracle，也不宣稱此範圍全部數值均已獨立證明。跨建置品質比較沿用固定原模型，保持既定五項驗收，不把 worker 建議擴張成另一套動態模型或公開介面。
- driver 的五份完整來源由外層鎖定，binary 另行核對。單獨的 `program.source_sha256` 只有 `main.go`，不能取代外層來源鎖。每組 metadata 指紋與來源檔案也會在最後分析逐項核對。
- 七組已完成 120,000 更新及新程序恢復，完整評分、參數／最佳化器摘要與下一次更新相同。第一個完整配對為 seed20260925 的 OFF，兩種建置的公開載入快照、23,568 項保存參數及全部數值陣列相同，23,516 項最佳化器步數為 120,000、52 項凍結項目為零。現在的分析函式也已在這個真實完成配對上驗證，見 `first-pair-functional-verified.json`。其餘五組尚未通過，完整品質結論保持 pending。
- Root 的分類驗收工具原先誤用 1～10。driver 的 `score` 明確輸出 `got-1`，因此正確類別為 0～9。已先保存舊驗收對合法類別 0 的失敗，再確認修正能接受合法值並拒絕 -1／10。原工具、原訓練及執行中組別保留，補正只影響驗收與分析，沒有更動框架、driver、資料、初值、順序或預算。證據為 `validator-repair.json` 與 `analysis-controls.json`。
- 沙箱內完整測試的六個套件都在建立 localhost 測試伺服器時被拒絕。保留原失敗，允許本機連接埠後的完整一般／競態各 58 套件通過，5,778／5,777 個事件成功、22／23 個略過、0 個失敗，見 `engineering-verified.json`。沒有以略過測試處理這個限制。
- 最後分析重新核對每個成功回條、原始日誌指紋、精確命令、20 輪逐輪更新數、新程序結果及 23,568 項完整參數／最佳化器形狀。舊 reader 會接受失敗命令的 JSON，已先確認失敗案例再修正。Go 的負零序列化為 `-0`，Python 預設會把它解析成整數零，已用獨立 Go 程序證明並補保留符號。九項控制及已知錯誤互換案例通過，見 `analysis-selfcheck-final.json`。這些補正只影響 Root 的分析工具，原始分析來源按原指紋保存，沒有更動框架或訓練。
- 追加分工的兩個 Luna worker 均遇到額度限制，沒有產出新報告；Root 接手並親自執行上述獨立控制。原先完成的資料、driver 與機制報告保留，見 `delegation-errors-continuation-1.json`。
- 目前 11 項治理頂層測試及 31 個事件通過，見 `governance-preanalysis-verified.json`。這是分析前的檢查，完整成果與清理完成後的最後交付檢查仍須補上。原錯誤 coordinator 的 terminal handle 已結束，三組原訓練全部保留，接續只由修正後的 queue31714 執行，見 `original-queue-terminal.json`。

新重現目錄的 653,211,566 bytes 暫存及 41,797 個連結已清除，原生連結目標、810 份來源、18 個原模型檔、六份原資料、既有目錄與執行中的主訓練目錄保持。清理本身的報告與外層回條名稱相同，外層寫入回條時失敗，原報告及日誌保留。另以成功命令讀回現況，沒有重做刪除，見 replay-smoke-cleanup-confirmed.json。主訓練暫存的清理尚未完成。

本輪 OpenCode models 實際因 opencode.log 的 FileSystem.open 失敗，採專案指定第二選擇 gpt-5.6-luna/max，重現報告已完成。Root 讀完報告並核對來源，採用新工作／結果目錄處理保留證據的輸出衝突；worker 未讀的 manifest 不列為確認框架缺陷。

三個已完成 OFF 配對的最終評分、參數／完整保存摘要與下一次更新相同，六次新程序恢復通過。Root 初次比較整份 epoch 事件，誤把 train_seconds 差異寫進品質欄位，舊紀錄保留；逐欄核對確認 20 輪唯一差異為觀察時間，損失的 float64 位元與 development 評分相同，見 off-pairs-functional-verified.json。ON 與全 12 組品質分析保持 pending，沒有調參、改預算或早停。

## 最後分析驗收補正

Root 在記憶體中執行分析器原本的逐組與完成條件，使用一組已完成真實配對的日誌作正常控制。原檢查接受來源清單缺漏／重複、切分指紋或預算宣告不符，以及完成標記中的輪數／更新／恢復數不足或失敗旗標。16 項控制中有 13 項負向案例被錯誤接受，見 analysis-gate-red-result.json。這是 Root 的驗收工具缺口，不列為已確認框架模型缺陷。

補正後必須核對 6,000／2,000／2,000 數量、20 輪、120,000 更新、23,516 可訓練項目、三種固定切分指紋、完整且不重複的五份資料來源與 metadata 指紋，以及 12 組、20 輪、120,000 更新、12 次恢復和非失敗的完成標記。16 項控制全數通過，原九項回條／數值控制保持。七組已完成的 14 個真實 train／restore 宣告都符合新檢查，準備重現的六項控制再驗通過。完整分析在缺少完成標記時實際退出 1，沒有產生模型 probe 或品質結果，見 analysis-gate-verified.json。框架、五個 driver、協定、初始化、順序與訓練預算保持。

本輪可核對九個 OpenCode 免費模型，但外部審查執行在程序啟動前被自動審查拒絕，理由為這批檔案的目的地外傳授權不足。沒有 OpenCode 審查結果，Root 在本機完成上述控制，見 opencode-gate-review-rejected.json。

## 數值報告補正

Root 確認先平方再開根號會把有限差值 1e-200 算成零，把 1e200 算成無限大。改用標準函式 hypot，另核對最小正次正規值 5e-324。三個案例在原分析函式失敗，修改後距離均等於單一差值。六項距離控制、九項既有回條／數值控制、16 項驗收控制及六項準備重現控制通過，見 numeric-report-root-verified.json。正式框架、driver、協定與執行中訓練保持。

Luna 的唯讀審查使用修改前分析器，完整報告保存為 numeric-report-review.md。Root 核對公開 TrainingSnapshot、Parameters、AdamState 宣告與一個已完成真實快照：五個參數陣列與三個最佳化器陣列都是純數值、欄位名稱固定，步數只有 0 與 120,000。任意混合 JSON 或名稱含路徑符號的反例不屬目前模型的輸入。每份最終與 development 評分在成對計算前都先驗證預測長度，缺少預測的控制實際拒絕，因此另外三個反例沒有列為確認框架缺陷。數值距離補正是否影響本輪模型，須等 12 組完整狀態比較後判斷。
