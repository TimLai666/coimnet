# 真實單字元品質驗證

新單字元模式能學會訓練圖片，但三個種子皆未達到事前宣告的 80% 獨立測試門檻，也低於同資料的四個最近鄰對照 81.85%。本輪沒有證明模型已可實用。

四個最近鄰使用同一批 6,000／2,000 圖片，正確辨識 1,637／2,000。三個模型各自保存完整設定與最佳化器，由另一個程序載入後，評分、混淆矩陣、完整訓練快照及 bundle 檔案指紋相同。模型保留在專案內已忽略的 `models/TSK-11/quality-20261012/`，不作模型產品發布。

## 已確認的改善與限制

舊欄位模式的第一個讀出尚未收到圖片，最後欄缺少後續傳遞步。`aligned-columns` 補終止零輸入並對齊讀出與外部梯度。相同十筆圖片的控制實驗，訓練正確率由 10% 提升到 60%。舊的合法模式與保存物保持，完整 bundle 逐位元組比較通過。

`single-character` 以整張影像輸入及最後列分類取代欄位序列目標。第二次重複圖片輸入已改成零傳遞步，十張真實圖片的輸出與全部參數梯度完全相同。此模式同時改變輸入表示、編碼器容量及訓練目標，不能把全部成績差異歸因於時序。

訓練正確率約 99%，獨立測試約 72%，確認有明顯的泛化落差。是否主要來自缺乏停止判準、限制過度記憶的設定、影像表示或資料涵蓋，尚未用控制實驗分離。下一步應從訓練資料另切驗證集，用它決定停止時機，再以新的獨立資料驗證。

原先 1,000／200 圖片的開發結果與本次 6,000／2,000 正式結果資料量不同，不能當成相同條件的直接成績比較。[原始診斷](diagnostics/verification.json)保留所有失敗、原型來源與控制結果。

## 重現與工程驗證

[verification.json](verification.json)記錄命令、環境、來源指紋、實際結果與日誌。[程式及協定審查](review.md)區分原始碼審查及實際執行。`final/sources/` 保存實驗 driver 與協調程式，副檔名為 `.txt`，避免歷史 main 程式被 Go 當成一般套件一起編譯。原始位元組保持。

重現時使用 Go 1.26.5 與鎖定的 Insyra v0.3.4，在原生磁碟的 `runs/.tmp/real-task-quality-20261012/` 建立全新執行目錄與快取。官方資料檔放在其 `data/kmnist/`，用 `final/input-metadata.json` 核對 URL、授權、classmap 與每檔 SHA-256。依保存的來源與命令重建 driver，原 `realocr` main 只改名，資料讀取器與公開 OCR SDK 保持。本輪保留實際命令，程式拒絕覆寫既有模型。

## 生理機制範圍

這是人工連續核心上的真實單字元資料驗證，不包含自然頁面、果蠅接線優勢或全腦模型品質。OCR 模式沒有啟用化學調節、受體、LIF 或局部可塑性。框架中的受體位置只到神經元／區域分配，缺少實測受體分布與細胞內位置，一般訓練也尚未整合化學狀態，見[生理範圍審查](review.md#生理機制使用範圍)。原 91／91 是工程驗收，不能替代上述品質或生物證據。

工程驗證：完整一般與 race 各 57 個套件通過，格式、build、vet、相依性及 13 個治理專項通過。一般有 22 個、race 有 23 個測試略過，另有 3 個不含測試的套件，詳細名稱保留在 verification.json。57,028 個本輪暫存檔與 1,585 個快取連結已清除，來源、歷史證據及六份原資料保持，見[清理回條](cleanup.json)。
