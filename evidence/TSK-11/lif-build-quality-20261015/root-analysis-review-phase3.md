# 結果核對工具補正與工程驗證

本票的公開框架、LIF 演算法、固定協定與模型設定保持不變。先前審查指出的三項缺口屬本輪私有驗收工具，沒有證據顯示是框架數值錯誤。

## 採用的補正

- SDK：把既有工程與 SDK 回條的命令、內容指紋及日誌指紋固定在 `analysis-input-lock.json`，最終工具解析兩筆 event 並要求三項契約旗標通過。活動輸出／梯度是否不同是觀察值，不把它當成辨識品質改善。
- 索引：每組正式 selection 的四個索引指紋都必須等於事前協定。來源檔案與 metadata 指紋也須一致。
- 資料：六份固定預期指紋來自提交 `b4b9003` 已保存的資料紀錄，與本輪複本逐一核對，再固定在獨立輸入鎖。資料 manifest 自行更新不能替代這份預期值。
- 拒絕順序：資料的獨立預期指紋比對移到工程日誌與模型讀取之前。五項測試的初次結果為四通過、一失敗；最小順序調整後五項全通過，未修改測試。

## Root 親自驗證

`analysis-gate-verification-phase3.json` 保存實際結果、最終工具及測試指紋。五個拒絕測試與十個數值 helper 回歸通過，先前九項欄位負向控制另存 `analysis-gate-controls.json`。正式來源 812 份、原模型 18 份、driver、兩個執行檔及六份資料均重新核對相同。

完整一般測試為 58 套件、5,818 pass、22 skip、0 fail。完整競態測試為 58 套件、5,817 pass、23 skip、0 fail。兩者都從實際 JSON 日誌逐筆重算，並核對無重複 pass／skip 事件。
