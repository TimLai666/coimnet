# 固定 LIF 真實單字元辨識比較

本票交付同一資料、相同更新預算的 LIF 一般／競態建置與化學 ON／OFF 比較。五個驗收項目只由 ticket 104 追蹤，不把軟體測試通過當作任務品質或零 bug 的證明。

## 流程與責任

```text
原始 IDX 與 metadata -> 指紋及完整性驗證 -> 固定索引
公開 OCR 初值與輸入工廠 -> 新 LIF Trainer -> ON/OFF 訓練
                                   -> TrainingBundle -> 新程序恢復
固定評估 -> 預測、損失、完整狀態及下一次更新比對 -> 證據
```

原檔與舊模型唯讀。所有新模型、快取與工作檔放在本輪 `runs/.tmp/lif-build-quality-20261015`。公開 Network／Trainer／checkpoint 是整合驗證入口，沒有新增測試替身或框架抽象。LIF factory 的測試與實作由不同角色持有，Root 親自執行及審查。

| 操作 | 失敗與處理 | 驗收責任 |
| --- | --- | --- |
| 讀取資料 | 缺檔、空目錄、指紋或 IDX 失敗即停止，保存錯誤，不下載替代資料 | 104 原 loader 與 Root 資料核對 |
| 建立模型 | nil、錯誤形狀、已訓練或非連續初值明確拒絕，不丟棄已訓練狀態 | 104 factory 失敗測試 |
| 計算／更新 | 非有限值或 API 錯誤保留實際日誌，先排查資料／driver，不用改參數掩蓋 | 104 SDK 整合與工程測試 |
| 零化學作用 | 輸出、梯度、參數、最佳化器及更新計數應一致 | 104 neutral 對照 |
| ON 化學作用 | 保存輸出及梯度的實際差異，兩步 hard spike 相同不自動判缺陷 | 104 active 診斷 |
| 保存／恢復 | 新路徑排他發布，遇既有目錄拒絕；不同程序須重算分數及下一次更新 | 104 全部 12 組模型 |
| 評估 | 不更新模型，不調整參數，不挑最佳結果 | 104 snapshot 前後雜湊 |
| 中斷／部分成功 | 保留已完成程序及日誌，不把部分執行當完整 12 組 | 104 執行回條 |
| 清理 | 只移除本輪已保存證據且沒有開啟控制代碼的目錄，原有兩個目錄與模型保持 | 104 清理回條 |

配對比較使用同 seed、同圖片、同更新順序。三個種子只報描述性差異，不宣稱母體效益。資料集完整性、切分和訓練像素摘要已獨立核對；LIF 設定事前固定，不依結果選擇。

## 減法審查

- Won't List：不新增 OCR 公開設定、不改既有任務、原模型或依賴，不做生物歸因或全腦品質宣稱。
- 建議移除：完成接續與證據保存後移除本輪模型、資料副本與快取。
- 建議簡化：沿用原始資料 loader 與輸入／初值工廠，避免再寫一套影像處理與初始化。
- 需要留意：threshold 多 52 個可訓練參數，連續模型結果僅為背景，不能當容量相同的架構優劣比較。
