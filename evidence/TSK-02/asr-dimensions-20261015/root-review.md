# Root 審查：語音模型建構尺寸

公開原來源一般／競態各五個非法設定在負邊容量配置時 panic。凍結回歸一般／競態各有 12 個實際失敗事件及 5 個通過事件，包含 11 個非法子案例與父測試失敗。候選使同一回歸各 17 個事件通過，測試原文保持。

候選以既有 checkedAdd／checkedProduct 計算 nodes、edges、classes、encoder 與 readout，另檢查平台 int 與 float64 陣列位元組可表示。Validate、NewRecognizer 與保存形狀核對使用同一份計算結果。合法邊數等於原公式，邊序、亂數、訓練算式與保存格式保持。沒有新增任意尺寸上限，也沒有把實體記憶體不足改成可恢復錯誤的承諾。

完整 OCR／ASR 套件一般／競態各 370 個事件通過，原有 353 個事件逐項保持。每種建置的五個原始非法公開設定都在配置前回錯，三個 tiny 初始化快照保持。四組合法模型的完整設定、初始化、三次更新、保存狀態與下一次更新都與 107 基底相同。兩種建置各有四份舊保存物由候選新程序載入、四份新保存物由基底新程序載入，後續狀態相同，共 16 次跨版本新程序接續。48 個小型保存檔、78,168 bytes 已逐位元組保存，僅供相容性測試。

Root 第一版額外相容性 fixture 的第四組以 Window 16／Mels 6 建立，原有音訊前端即因濾波區間沒有 FFT bin 拒絕。這是驗收 fixture 錯誤，並非候選缺陷。保留失敗日誌與原 driver 後，第四組改用已驗證可產生特徵的 Mels 4／Hidden 8，兩側皆用相同新 fixture，原始凍結回歸未變。修正後的完整對照見 candidate-compatibility-verification.json。

這些是 macOS arm64 的執行結果。32 位平台僅有靜態算術證明，未宣稱實際執行。正式採用與完整框架工程驗收仍須另行完成。

減法審查：共用既有整數檢查與三個實際使用入口的尺寸結果，不新增資源管理器或 panic 包裝層。
