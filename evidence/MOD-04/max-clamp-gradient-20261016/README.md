# 最大受體作用與夾限的訓練驗證

負係數、最大受體作用與作用上下限的指定組合通過驗證，這輪沒有確認新的正式程式缺陷。已修正 ticket21 的數學說明，並加入永久整合測試。正式模型計算、API、保存格式及依賴保持原樣。

最大作用先選原始受體佔用率，再套用係數。佔用率0.8／0.2、係數−0.5時，增益是0.6；輸出梯度為2時，兩筆佔用率梯度為−1／0。負係數不改變選中的受體。

432個參考座標全部能排除零梯度，最大絕對誤差為2.0321e−5，低於事前固定門檻。刻意把最大值改成總和，或忽略作用夾限的梯度，測試都會失敗。後者也被兩組增益上下限的獨立數值參考抓到。

格式、build、vet、固定 Insyra v0.3.4、模組校驗與工程治理檢查通過。原有各6,477個終端測試事件保持，只新增各65個通過。完整結果見[驗收](verification.json)、[工程結果](engineering-verification.json)、[診斷](diagnostic-verification.json)、[永久測試](regression-verification.json)與[錯誤植入驗證](mutation-verification.json)。

這是人工雙節點CPU純量驗證。公開診斷有五種來源，永久測試重用既有三通道人工範例。LIF採明示的替代梯度規則，沒有對硬放電做中央有限差分，也沒有新增獨立完整LIF梯度參考。第一步的化學證明不表示後續每列都處於相同夾限狀態。本票沒有新的全腦、真實辨識率或生物校準結果，也不能證明整個框架完全沒有bug。

命令、環境與來源指紋保存在驗收JSON。正式測試為[chemical_max_recompute_test.go](../../../learning/chemical_max_recompute_test.go)，可由專案的測試流程執行。診斷五份程式、56份SDK快照、錯誤植入檔及模組來源清單已保存於[preserved-work.tar.gz](preserved-work.tar.gz)，供新工作目錄重建；原證據目錄拒絕覆寫。

原始失敗紀錄保留：新測試錯把初始狀態導數長度寫成零，已依既有API改為節點數；首次完整測試的本機HTTP綁定被沙盒拒絕，未改程式或測試，改以原授權的本機驗收重跑。詳見[測試預期值修正](test-oracle-correction.json)與[環境限制](sandbox-limitation.json)。

最後31項治理檢查通過，本輪28,022個暫存項目、1,668,319,814 bytes已清除。18個原模型、6份必要資料、15,046份原始模組檔與其他既有工作保持，見[清理回條](cleanup.json)。Git交付由驗收JSON與delivery.json記錄，遠端讀回完成後才結束本票。
