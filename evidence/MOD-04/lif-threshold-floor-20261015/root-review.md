# 門檻下限修正審查

## 結論與影響

P2 已確認缺陷：有限負向化學偏移與有限基礎門檻相加時，暫時結果可能超出 float64 的負向範圍。一般模擬依既定公式取有限下限，耦合 LIF 及混合核心卻在投影前回錯，導致同一模型的模擬與訓練不一致。這次證據只涉及極端有限設定的運算正確性，沒有真實任務品質改善結論。

原始 `[-2^1023, 0]`、raw 0、shift `-MaxFloat64` 的公開重現與精確有理數參考見 `reproduction.json`。候選電位恰等於投影下限，替代梯度為 1，可排除梯度因極大間距自然歸零的假通過。

## 契約與修改

主規格 §8.2 允許明示的有界投影，ticket 21:55–57 與 `docs/model-and-mechanisms.md:54` 已指定 `max(theta + shift, theta_min)`。`ENG.md:81` 要求供放電使用的最終門檻可表示。Root 依此確認投影的數學結果，沒有新增使用者設定、保存格式或另一套機制。

整棵 dynamics 以 `shifted := theta` 搜尋，該提前拒絕恰有兩處：`lif_coupled.go:249` 與 `mixed_coupled.go:194`。完整 diff 只將有限值檢查移至下限分支之後，保留原錯誤字串、原加法順序、比較、零偏移分支與導數旗標。沒有新增半值加法或 helper。

- 有限 `shifted` 的比較、結果與原版完全相同。
- 負向超範圍的和低於有限下限，依既定 max 公式得到該下限。
- 正向溢位不符合下限比較，由原有限值檢查拒絕。
- NaN／±Inf 的調節輸入在原驗證入口拒絕，NaN 也不可能通過下限比較。
- LIF 與混合反向既有的 floor flags 會清除基礎門檻、適應與偏移的直接導數。事件對電位與輸入的替代梯度保留。
- LIF 重算的前向與反向 replay 都共用 `forwardLIFCoupled`，沒有另一份門檻實作。

合法前向的基礎門檻先驗證有限，適應從零開始且 Beta 非負，慢速穩定偏移限制在 `[0, HMax]`。因此投影前的 `theta` 不會先由合法歷史變成負無限大。私有 checkpoint 目前只由合法 trace 產生；假設未來開放注入負適應並不是目前可觸發的缺陷。
