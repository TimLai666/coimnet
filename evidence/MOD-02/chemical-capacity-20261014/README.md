# 化學機制設計稽核與配置容量修正

正常化學路徑目前沒有找到明確違反既定設計的輸出或梯度錯誤。非法容量宣告則確認四類驗證缺陷，會中止運算，已由 ticket 87 修正。混合連續與脈衝神經元的完整化學反向組合仍缺少獨立對照，不能宣稱所有機制已完全驗證。

## 已確認的缺陷與修正

比較基準為 `57cc92d2864bd19f2424a4daa57edad60ad2763d`。公開診斷共有 21 個獨立小型程序，包含 15 個非法宣告及六個正常來源控制。修正前重現 13 個 `makeslice: len out of range` panic，另有一個濃度區域設定被錯誤接受。餘下一個非法案例原本即因 Tau 形狀不符而回錯。

| 類別 | 影響 | 修正後結果 |
|---|---|---|
| 來源釋放向量 | 通道數可用 int 表示，配置 float64 所需位元組卻不可表示，Build 或 Release 會接受後崩潰 | 宣告與 standalone 入口在配置前回錯 |
| 控制器活動視窗 | 節點數或整個摘要視窗不可表示，運算可能崩潰 | Controller 與 MemoryController 在複製、觀察活動前拒絕，既有活動與梯度保持 |
| 化學濃度與區域網格 | NewChemistry 接受不可表示的 Regions，NewState 或 EnableChemistry 崩潰 | 建構前拒絕，持續個體的完整快照與最後報告保持 |
| 效果節點向量 | ApplyEffects 對不可表示的節點宣告配置陣列 | 回錯並回傳 nil 陣列 |

修正後 15 個非法案例全數回錯，沒有 panic 或逾時。正式回歸的修正前結果為 31 個失敗事件，修正後 34 個通過事件、五個頂層測試。兩份新測試及 453 份既有測試均以指紋凍結，實作 worker 沒有修改測試。

這些缺陷的已確認影響是非法設定中止運算。沒有證據顯示它們會降低正常辨識率，修正也沒有調整生理公式或訓練參數。

## 正常機制的設計核對

[獨立稽核](mechanism-design-review.md)包含六類機制的設計、實作與現有直接驗證。[Root 審查](root-review.md)保存主 agent 的採用判斷。

| 機制 | 本輪結論 |
|---|---|
| 來源釋放、清除與區域運輸 | 明示來源的非負釋放先更新濃度，再進入神經步驟，既有手算與反向測試涵蓋單獨元件 |
| 受體位置、親和性與狀態 | 位置選擇濃度區域，Hill 曲線計算作用量，未知與不反應狀態分開記錄。位置沒有建立獨立膜電位 |
| 敏感度、偏移、觸發門檻與局部學習 | 受體效果先於神經核心，局部學習在神經核心之後，正常與中性效果有既有直接驗證 |
| 神經訊號到損失與梯度 | 來源控制器的活動梯度會回到一般訓練。控制器參數採獨立目標訓練，符合目前明示契約 |
| 活動、重置與恢復 | 八個生命週期診斷全數通過，前後輸出逐位相同。初始神經來源缺乏先前活動時的拒絕是既定設計 |
| 混合連續／脈衝核心 | 實作有接入一般化學訓練，但完整組合反向缺少獨立參考，已列入 AGENTS.md Follow-ups |

受體平均採同一受體產生的所有記錄，符合目前程式明示的工程定義。RewardMapper 的額外清除須由呼叫端明確傳給 Kinetics.Step，一般 ChemicalConfig 沒有自動接入宣告。兩者都沒有本輪已確認的設計矛盾，不在這次修正改寫算式。

混合核心的硬脈衝採替代梯度。後續完整組合驗證必須使用獨立同規則反向參考或 test-only smooth 模式，不能用硬 0/1 輸出的普通中央差分判斷梯度是否正確。

## 相容性與工程證據

- 32 組合法個體的輸出與完整快照逐位相同，共 487,897 bytes。此處 mixed 是 gradient＋plasticity 學習模式，並非混合連續／脈衝核心的完整組合測試。
- 八組活動生命週期與六組正常來源控制前後相同。
- CLI 三個新程序的 80＋40 步接續與 120 步連續訓練保存結果逐位相同，共 1,179 bytes。
- [工程摘要](engineering-summary.json)從原始 Go JSON 事件、命令退出碼及指紋產生，包含完整 unit／race、略過項目、格式、build、vet、相依性與上述比較。
- [驗收](verification.json)連結工程、治理、清理與交付證據。原始失敗、成功重跑及 worker 紀錄均保留，worker 回報不取代 Root 實際驗證。

## 重現與證據保留

正式回歸命令：

```sh
go test -count=1 -json -timeout=3m -run '^(TestChemicalCapacity|TestIndividualChemicalCapacity)' ./modulation ./learning
```

完整工程驗證使用 `gofmt -l`、`go build ./...`、`go test ./...`、`go test -race ./...`、`go vet ./...`、`go mod verify` 與 `go list -m -json all`。治理入口為 `go test -json -count=1 -run '^Test(NoTelemetry.*|FormatIndex.*|Governance.*)$' -timeout=10m .`。每個實際命令、時間、環境、退出碼與日誌指紋保存在同名 JSON 回條。

此次 GOMODCACHE、GOCACHE、GOTMPDIR 及 TMPDIR 全部在專案 `runs/.tmp/chemical-entry-audit-20261014`。依賴固定為 Insyra v0.3.4，離線驗證只在任務快取中連結本機既有唯讀依賴，沒有更新依賴或下載新版本。重跑時需依專案規則準備自己的已忽略快取。容量、活動與相容性診斷程式以 `.go.txt` 保存，驗證 runner 與摘要程式以 `.py.txt` 保存。

日誌使用 gzip 壓縮。JSON 中原 `log` 欄位記錄執行當時的暫存位置，`retained_log` 指向本資料夾內的實際保留檔案。初期回條沒有該欄位時，原始日誌使用對應的同名 `.log.gz`。正式驗收的 `test_log` 列出可讀回的保留日誌。

## 驗證限制

本輪執行平台為 darwin/arm64。32-bit 算術按 strconv.IntSize 核對，沒有 32-bit 實機結果。容量驗證拒絕數學上不可表示的配置，不能保證一般大型合法配置有足夠實體記憶體。略過的真實資料、全腦及特定裝置驗證以工程摘要的逐項清單為準。

這次沒有重新訓練真實 OCR，也沒有量測辨識率改善、生物定量正確性或全腦泛化。整個框架零 bug 的目標保持未完成。
