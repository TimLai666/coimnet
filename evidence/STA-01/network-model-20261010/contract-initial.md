# Root contract: network model bundles

User authorization: the framework must support saving models to network disks. Current project is macOS SMB; hardlink and exclusive rename fail ENOTSUP, ordinary writes and directory fsync work. Use existing checkpoint bundle v2 and Save/LoadModelPackageBundle, Save/LoadIndividualBundle, Save/LoadTrainingBundle. Keep file names, schemas and bytes unchanged. Single-file publication and download/store/params are not weakened or advertised as network-compatible.

Flow: validate -> exclusive Mkdir destination -> write/sync/close arrays and document -> exclusively create/write manifest last -> sync bundle and parent -> return status. An existing directory/file must never be changed. The manifest is the existing completion record: absent/truncated invalid manifests cannot load. Full manifest written is logical publication, distinct from confirmed durability. After publication, cleanup must never remove the bundle; cancellation/close/sync errors report published status. Before publication, failed owned directory is removed. Filesystem errors including ambiguous network failures remain errors, never success claims. No unsupported operation is hidden behind ordinary rename or symbolic links.

Implementation slot: checkpoint/bundle.go only. Keep shared write helper reusable; it may return a full-write flag so manifest publication and error cleanup differ from payload writing. Keep limits, strict decoding, nonregular-file protection and semantic restoration checks. No dependency or API/schema changes.

Test slot: new checkpoint/bundle_network_test.go only. Use public bundle APIs and existing fixtures; no production edits or new test-only seams. Expected: model bundle round trip; concurrent writers have exactly one winner and one loadable result; cancellation before publication removes only owned output; cancellation after complete manifest returns context.Canceled but leaves bundle loadable; truncated manifest never loads; original input and old files unaffected. Existing bundle roundtrip tests cover individual/train restoration including LIF/plasticity/chemistry and large arrays.

Acceptance: 1 Root-reviewed RED on actual SMB with frozen new tests. 2 model/individual/train bundle operations, no-overwrite and failure regressions pass normal and race on SMB. 3 fresh-process restore/continuation and existing v2 artifact read/byte comparisons. 4 all applicable build/full-suite/race/vet/module/governance checks and honest native-versus-network limits. 5 docs, root/independent review, fingerprints, temporary cleanup, commit/push/readback.
