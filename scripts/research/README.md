# 核心架構原型實驗室

這裡的腳本用 PyTorch 重寫 `dynamics.Continuous` 的連續核心數學，用來快速篩選架構假設。有效的機制再實作進 Go 框架，並在框架上重現與量測。腳本不屬於框架本身，結果以 Go 框架上的重現為準。

## 任務與規則

- 任務：KMNIST 逐欄序列分類。每張圖 28 步、每步輸入 28 個像素，最後一步讀出 10 類 logits，用 softmax cross-entropy 訓練。官方 60,000 張訓練、10,000 張測試全部使用。
- 訓練：AdamW、batch 128、8 epochs、梯度裁切 1.0。
- 公平比較：每個模型都先在驗證集各自挑 lr（`--val` 把訓練集最後 6,000 張留作驗證），再用挑到的 lr 在測試集跑 seed 0/1/2。驗證集只用來挑 lr。
- 同硬體比較要同時比參數量、記憶體峰值與推論延遲，三項在同一台機器量測。

## 腳本

- `seqlab.py --data <kmnist 目錄> --spec '<JSON>' [--lr 0.01] [--seed 0] [--val] [--device cuda]`：訓練並輸出 `RESULT {...}`。`spec` 範例：
  - `{"model":"coim","topo":"random","n":512,"n_in":128,"n_out":128,"k":22,"gate":"local"}`：稀疏核心，512 顆神經元、每顆 22 條輸入邊，加依輸入電流調整整合速度的閘門（每顆 2 個參數）。
  - `{"model":"coim","topo":"dense","n":120}`：密集核心。
  - `{"model":"gru","h":64}`、`{"model":"lstm","h":56}`、`{"model":"rnn","h":120}`：PyTorch 內建基準。
- `latency.py '<spec>'`：單執行緒、batch 1 的單張推論延遲與記憶體峰值（RSS）。

Go 框架上的對應程式是 `examples/seqkmnist`（`--gate` 開啟閘門，`--save`／`--load` 存取模型，`--bench` 在全新程序裡量測延遲與記憶體）。

## 結果（Go 框架，多台機器，驗證集判定，2026-10-20～21）

以下都用 `examples/seqkmnist`，softsign 閘門＋softsign 活化，n=512 k=12（13,056 參數），8 epoch，`--val-count 10000`（訓練集最後 10,000 張當驗證集）。逐筆結果在 [`results/val-results-2026-10-21.tsv`](results/val-results-2026-10-21.tsv)，欄位為機器、裝置、變體、lr、seed、參數、驗證、測試。

判定規則在看到結果前寫定：

1. 每個變體在 lr 0.01／0.02／0.03 中挑驗證準確率平均最高的，測試集不參與挑選。
2. 每個機制在自己的最佳 lr，和 ref 在 ref 的最佳 lr，以同 seed 配對相減驗證準確率。
3. 配對差平均超過 +2 倍標準誤才算有幫助，低於 −2 倍標準誤才算有害，其餘記為看不出差別。
4. CPU（float64）與 GPU（float32）的結果不放進同一張判定表。

## 結果（Go 框架，新形狀對 GRU／LSTM，驗證集判定，2026-10-24～25）

新形狀：節點較少、每個節點的輸入邊較多，讀出層讀所有節點（`--readout-nodes` 等於 `--nodes`）。KMNIST 驗證集（訓練集最後 10,000 張），訓練 12 個 epoch，雙方都在驗證集各自挑 lr。我們是 Go 框架 GPU 路徑（表中數字來自 Mac M3 Metal），GRU／LSTM 是 `seqlab.py`（ubuntu-1 RTX 4070 CUDA）。每格是 10 個 seed 的平均，± 是平均數的標準誤，逐筆結果在 `results/val-results-2026-10-21.tsv`。

|---|---|---|---|---|---|---|
| 16.4k | n256 k36，0.02 | 96.98±0.04 / 92.88 | h59，0.01 | 96.81±0.03 / 92.46 | h50，0.01 | 96.53 / 91.99 |
| 18.2k | n384 k24，0.015 | 97.19±0.05 / 93.16 | h63，0.01 | 96.87±0.03 / 92.80 | h53，0.01 | 96.54 / 92.12 |
| 21.2k | n384 k32，0.01 | 97.28±0.04 / 93.33 | h69，0.01 | 96.95±0.05 / 92.98 | h58，0.01 | 96.73 / 92.58 |
| 25.1k | n512 k28，0.01 | 97.38±0.05 / 93.72 | h76，0.01 | 97.12±0.04 / 93.07 | h65，0.01 | 96.98 / 92.97 |
| 29.2k | n512 k36，0.01 | 97.43±0.02 / 93.87 | h83，0.005 | 97.17±0.06 / 93.46 | h71，0.01 | 97.07 / 93.18 |
| 45.1k | n768 k40，0.01 | 97.77±0.03 / 94.34 | h107，0.005 | 97.48±0.03 / 93.99 | h91，0.005 | 97.35 / 93.81 |

- 每個大小都贏 GRU 0.17～0.33 個百分點、贏 LSTM 0.36～0.65 個百分點（驗證集），測試集贏 GRU 0.35～0.65 個百分點。差距都是標準誤的 3 倍以上。16.4k 要用 lr 0.02 才領先，lr 0.01 時與 GRU 打平。
- 同一組設定與 seed，在 RTX 4070 與 GT 1030（都是 NVIDIA、Vulkan）上結果逐位相同；Mac Metal 的逐筆數字不同，但 10 個 seed 的平均一致（29.2k：Metal 97.43、Vulkan 97.47）。
- 推論延遲（雲端 Xeon 單執行緒、batch 1，p50）：21.2k 的 n384 k32 讀 384 個節點是 0.60 ms，舊形狀 n1024 k12 是 0.81 ms，正確率相同；GRU h67（20.2k）0.59 ms、LSTM 約 0.28 ms。29.2k 的 n512 k36 是 0.80 ms，GRU 0.69 ms、LSTM 0.28 ms。記憶體峰值約 60 MiB，GRU／LSTM 約 227～232 MiB。
- 讀出層從 128 個節點加到全部節點，比把同樣的參數加在核心上有效：29.2k 的 n512 k36 讀 512 個節點（97.43～97.47），與 35.6k 的 n1536 k16（97.47）相同，參數少 18%。輸入節點加到 256 沒有幫助。
- 12 個 epoch 與 16 個 epoch 結果相同，8 個 epoch 低約 0.3 個百分點。暖身比例 5%～30%、延遲 2 步、時間常數上限 4 或 20 都沒有改善。

## 目前結論

- 同參數下，寬而稀疏的核心（512 顆、每顆約 22–24 條輸入邊）比密集核心好。
- 依輸入電流調整整合速度的閘門穩定有效，每顆神經元只多 2 個參數。
- 加上閘門後，正確率超過同參數 LSTM，比 GRU 低約 0.25 個百分點；記憶體較省，單張延遲較慢。
- softsign 版正確率與 sigmoid 閘門相當，推論延遲少約 30%。
- 每顆神經元的輸入邊從 22 減到 12，驗證集只差約 0.5 個百分點，參數少 28%，邊數是延遲的主要成本。
- 稀疏累加已接近純量運算的上限（約 1.27 ns／邊），延遲要再降需要改變運算方式，例如批次或向量化。
- 同參數（約 13,000）下，k=12 的稀疏核心正確率比 GRU 高約 0.24 個百分點，同機延遲相當，記憶體約為 1/9。
- 這塊果蠅視覺回饋神經元的真實接線，在這個任務上比打亂或隨機接線低約 0.3 個百分點；決定表現的是每顆神經元的邊數，不是誰接到誰。
- 在驗證集判定下（GPU 5 個 seed、CPU 4 個 seed），閘門是唯一確定有幫助的機制，關閉後驗證掉 0.6 個百分點。Dale 定律有害。延遲、時間常數上限、化學調節、sigmoid 與 tanh 的替換都看不出差別。
- 視葉、ALPN、DAN 與 ALPN＋DAN 的真實接線在字元辨識上都沒有勝過打亂或隨機接線。視葉原本處理動態視覺，真實接線的價值可能要在偵測移動方向之類的任務上檢驗。
- 依細胞類型綁參數不是便宜的放大方式：放大神經元幾乎不進步，同參數量的隨機不綁模型明顯較好。
- 隨機不綁模型的驗證準確率在約 2 萬參數趨平；15,000 參數以上 lr 0.03 比 0.02 低 0.5～1 個百分點。
- 同參數下，少節點、多輸入邊、讀出層讀所有節點的形狀，在 16k～45k 參數每個大小都勝過 GRU 與 LSTM；21k 時推論延遲與 GRU 相當，記憶體約為 1/4。
